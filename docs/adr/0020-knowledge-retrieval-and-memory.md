# ADR-0020: Versioned knowledge retrieval and verified memory

- **Status:** Provisional for the synthetic fixture; live store integration remains unverified.
- **Context:** Phase 06 already provides three original CC0 synthetic manuals, tenant/site document records, paragraph chunks, an optional unbounded vector column, and a tenant-scoped derived Neo4j asset graph. There was no retrieval API, immutable source version citation path, vector index, or verified resolution memory. The official project reference prompts remain absent.
- **Decision:** Keep accepted operational events in Postgres as canonical; keep Neo4j derived. Add a versioned manual/chunk model with exact character offsets and hashes, approved classifications only, revocation audit, Postgres lexical search, pgvector 64-dimensional HNSW search, and tenant/site scope predicates. Current retrieval uses only the deterministic `fixture-hash-v1` embedding, explicitly marked as fixture; there is no production embedding provider configured. Hybrid ranking combines lexical, vector and optional graph relation signals. Source text is HTML-escaped and passed to model context as bounded, explicitly untrusted quoted data.
- **Citations:** Manual citations bind document ID, source version, chunk index, source character offsets and SHA-256. Event citations bind canonical event UUID, occurrence timestamp and sequence. Citation resolution rechecks tenant/site scope, classification, current version/revocation and content hash. Old versions are retained but excluded from current search; administrators can revoke a version with a local audit record.
- **Memory:** Only explicit human verification creates a memory fact. Facts store reviewer, tenant/site, revision, conflict group, classification and validated document/event provenance. Contradictory facts remain in the group as disputed revisions; no automatic model training or silent overwrite is performed. Viewer reads honor PUBLIC visibility.
- **Offline:** The web client caches only server-approved current manual content in the existing IndexedDB `manuals` store. Offline fallback is lexical-only and visibly stale; citation freshness and graph calls require the API.
- **Migration impact:** Additive raw SQL migration `007_knowledge_retrieval_memory.sql` adds versioned source/chunk/vector, source audit and verified memory tables plus FTS, scope and HNSW indexes. Existing `world_documents` and `world_document_chunks` rows are preserved. Seed now writes versioned records in addition to the legacy document tables. No shared wire contract or IndexedDB version changed. Migration coordinator ordering was corrected: raw 001-004, Alembic identity 0002, raw 005 onward, then Alembic head (0003 world-site constraint).
- **Consequences / open gates:** The hash embedding is not semantic AI. Fixture evaluation does not validate real plant questions. Postgres migration, seeded document vectors, scoped vector recall, revocation persistence, cross-tenant DB isolation, real Neo4j graph query/rebuild parity and browser offline caching remain unverified without running services/browser. No restricted documents are ingested; current document API supports synthetic fixture sources only.
