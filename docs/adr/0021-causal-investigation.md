# ADR 0021: Bounded causal investigation

- **Status:** Accepted for the synthetic fixture implementation; production causal validity is not established.
- **Context:** Synthetic incident triage needs explainable candidate ranking without presenting an LLM score as probability or exposing hidden evaluation labels to runtime.
- **Decision:** Rank only deterministic anomaly candidates using frozen robust-z evidence and explicit fixture weights. Interpret `FEEDS` source-to-target and `DEPENDS_ON` prerequisite-to-dependent. Preserve counterevidence, time-order contradictions, source sample references, assumptions, and uncertainty. All outputs remain hypotheses; the service returns no operational actions. Hidden labels are consumed only by `scripts/evaluate-causal.py`.
- **Persistence/API:** Additive migration 008 stores tenant/site scoped investigation snapshots with unique tenant/site idempotency keys. `POST/GET /v1/causal/investigations` requires an authorized site; starting is limited to owner/admin/operator. A canonical incident event and visible affected asset are required. The current implementation runs deterministic scoring only; a structured model adapter is not configured.
- **Consequences:** Existing data is unchanged. Environments must apply migration 008 before readiness succeeds. Rollback is not automated; investigations should be retained as audit snapshots. Synthetic weights and the dependency direction rules are provisional pending the missing authoritative contracts and engineering validation. Database/FK/query performance and UI build need live service checks.
- **Security:** Query scope is constrained by tenant/site membership and visible classification; telemetry is selected only from that scope. Runtime never reads the holdout file. Input graph size, depth, observation count, score and output counts are bounded. No raw external prompt payload or operational advice is produced.
