# ADR 0023: Shared command-center design system

- **Status:** Accepted for the existing synthetic demo UI.
- **Context:** Existing route pages had inconsistent light-only styles and page-local workspace choices. Several routes use fixture data, while others read tenant/site scoped APIs. Required product reference prompts are absent.
- **Decision:** Add a global responsive application shell with graphite/slate dark default, explicit light theme, semantic status tokens, breadcrumb, role-labeled organization/site selector, route navigation, canonical incident notification drawer, and keyboard searchable route palette. Preserve existing workflows and expose shared accessible UI primitives plus a specimen-only `/design-system` inventory route. Keep component specimens under `components/demo` so they are not operational data.
- **Accessibility:** Visible text accompanies status dots; primary dark/light foreground, muted and accent tokens meet static WCAG AA contrast checks; all interactive elements receive focus outlines; palette and modal confirmation trap Tab focus; Ctrl/⌘K opens route search; Escape dismisses overlays; reduced-motion preference disables animation.
- **Consequences:** No SQL migration or shared wire-contract change. Workspace selection is stored as a convenience in localStorage and is never authorization; API requests still carry tenant/site and use server authorization. Role labels distinguish viewer access, while write controls remain API/route gated. Notification contents come from authorized canonical incidents. Existing fixture-oriented routes remain visibly synthetic.
- **Limitations:** Browser screenshots at 1440/1024/390, Playwright keyboard flows, semantic typecheck and rendered overflow/contrast inspection were not available because the workspace Next/Playwright packages and web server could not be restored in this environment. The token contrast check is static and does not replace rendered accessibility evaluation.
