# ADR-0018: Authenticated peer mesh protocol boundary

- **Status:** Provisional security primitives and tenant device discovery implemented; signaling, transport wiring and live peer acceptance remain blocked (2026-11-16).
- **Context:** The registry has device ECDSA P-256 signing keys; events carry tenant/site scope and sequence/revision; privacy rules already define a PUBLIC-only, consent-required `peer/event_replication` destination. The official reference prompts remain absent.
- **Decision:** Pairing uses registered signing identities to verify consent-bound ECDH P-256 handshakes. HKDF-SHA-256 derives direction-separated AES-GCM keys, nonce prefixes, and a transcript-bound short-lived session token. Peer envelopes are signed, bounded to 64 KiB, PUBLIC-only, limited to observations/annotations, and bind tenant/site/session/device IDs, sequence and <=60-second expiry. Replay state advances only after cryptographic verification. The WebRTC DataChannel adapter defaults to no ICE servers; app-level encryption and signatures are still required.
- **Policy:** Only a reviewed, consented, sanitized ShareArtifact from same-tenant PUBLIC references can be sealed. Received peer material is provisional and is not a canonical event. Device sync remains the only canonical write path and rejects `source=peer`. Incident actions are never sent for approval or execution over peer.
- **Consequences:** Device inventory and active public-key lookup API routes are available to eligible active organization members. A session lasts at most five minutes, so device revocation prevents fresh pairings but cannot instantly terminate an already-derived partitioned session. There is no signaling service, TURN configuration, pairing UI, DataChannel-to-durable-queue wiring, or canonical resync flow yet; no reachability or offline discovery is claimed.
- **Migration impact:** No shared contract version or SQL schema change. API surface gains `GET /v1/organizations/{organization_id}/devices/peers` and `GET /v1/organizations/{organization_id}/devices/{device_id}/peer-key`. See `docs/peer-mesh.md`.
- **Verification:** 15 hybrid-web direct tests and 14 targeted API security tests passed. Actual two-browser pairing, WAN/LAN WebRTC transfer, network partition, and native discovery were not run.
