# ADR-0017: Offline state, synchronization boundary, and restricted vault

- **Status:** Provisional browser implementation; authoritative requirements are missing (2026-11-15).
- **Context:** Phase 05 sync accepts only PUBLIC/INTERNAL device events and there is no server-issued offline policy lease endpoint. The app currently caches an identity display lease, which does not authorize offline writes.
- **Decision:** Cache a versioned, narrow service worker shell and allowlisted public fixture assets only. Never cache API, sync, auth, or token responses. Keep append-only safe event drafts in IndexedDB with mutable delivery state in a separate store; reject confidential/restricted classifications from the sync outbox. Keep restricted local records in AES-256-GCM vault records with a fresh 96-bit WebCrypto nonce per encryption and tenant/record/version authenticated additional data. A nonextractable device CryptoKey is structured-cloned in IndexedDB. Store inbox, snapshots, manuals, and inference attempts in separate stores. Outbox retries are capped exponential backoff with jitter; batch processing is bounded at ten and duplicate ACK is terminal.
- **Authorization:** A local cached identity is display-only. No offline lease is issued by this phase, and no offline draft is submitted to the API. Sync must remain disabled until a server-issued, scoped, revocable, expiring policy lease and cursor/revision allocation are specified and implemented. Server conflict resolution remains the existing event API's explicit snapshot/revision reconciliation.
- **Lifecycle:** Organization switch and sign out warn about pending drafts and clear that tenant's IndexedDB records after confirmation. Quota failure is surfaced to the caller; the UI offers storage settings/removal through the browser, not silent loss. Native clients must use Keychain/Keystore adapters.
- **Threat model:** AES-GCM protects vault bytes from casual offline inspection while the origin key remains unavailable. It does not protect from same-origin XSS, a compromised browser/device/profile, malicious extension, physical memory access while unlocked, browser eviction, or loss/corruption of IndexedDB. A nonextractable key is not equivalent to hardware-backed custody. No restricted bytes go to cache, outbox, service-worker diagnostics, or app logs.
- **Migration impact:** New IndexedDB database `nexus-offline-v1` version 1, no server SQL migration and no shared wire contract change. Tenant clearing is destructive to local pending drafts only after a user warning. Future schema evolution needs explicit cursor migrations and recovery rules.
- **Verification:** See `docs/evidence/phase-09.md`; browser two-device, live offline model, server lease, and API conflict/ACK integration gates remain open.
